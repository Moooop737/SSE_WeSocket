01 · CONCLUSION

一句话结论与 story 边界

先把「这格做了什么」钉死，再看代码。2.4 不负责编号解析，也不负责 trace 面板；它负责「点开之后看到什么」。

03 · GLOSSARY

小白词典

这些词在本页反复出现；先用一句人话记住，再看代码。

UIMessage.parts
AI SDK 的消息不是一段字符串，而是 parts 数组：text、reasoning、tool-retrieve 各占一段。快照就住在 tool part 的 output 里。
tool-retrieve
模型自己调用的检索工具。它的 output 里有 hits（命中数组）、两路计数和 error；前端按 part 名找它，不另打 /retrieve。
快照
回答那一刻的命中副本：正文、块号、偏移、标题、URL 都在消息里。来源后来被删，快照本身不会消失。
chunkId / resourceId
chunkId 指向一个块，resourceId 指向块所属的资源。引用标记按 chunkId 找块；「来源已删除」按 resourceId 查资源。
404 / 410
404 = 找不到（当前用它表示资源不存在或已软删）；410 = 曾经存在、现在没了。2.4 只用 404，410 条款已作废。
软删
DELETE 不物理删 resources 行，只写 deleted_at；chunks 会在同一事务里物理删。GET /resources/:id 过滤 deleted_at。
抽屉 / dialog
从右侧滑出的浮层，语义是模态对话框。2.4 只提供内容；焦点、Esc、Tab 圈、滚动锁是共享 Drawer 的职责。
来源标识
URL 资源显示可点链接；粘贴内容没有 URL，用标题（Markdown 一级标题或首个非空行）加唯一 dataUri 指向唯一 Resource。
hono-crud read
Epic 3 起四张表的 list/read 交给 hono-crud。resources 的 read 仍按 deleted_at 软删过滤，响应信封是 resource。

121/** 同一轮里可能重查 1–4 次：每次的输出都在模型的上下文里，引用可以落在其中任何一次。按 chunkId 去重。
122 * 重复召回时留**最后一次**的那份：分数/名次要和「面板显示最新战果」的口径一致。
123 * Map 的插入顺序仍是首次出现，所以引用列表的顺序不受影响。 */
124function collectHits(Parts: ToolPart[]): RetrievedHit[] {
125 const Seen = new Map<string, RetrievedHit>()
126 for (const Part of Parts) {
127 if (Part.state !== 'output-available') continue
128 const Out = Part.output as ToolOutput | undefined
129 if (!Out || !Array.isArray(Out.hits) || Out.error) continue
130 for (const Hit of Out.hits) Seen.set(Hit.chunkId, Hit)
131 }
132 return [...Seen.values()]
133}

07 · DECISIONS

关键取舍与容易踩的坑

这一节回答「为什么这么做、否掉了什么、哪里会静默失效」。先看四张取舍卡，再看坑清单。

01

快照 vs 重新取 chunk

重取会得到「现在」的块，不是「回答当时」的块；来源删了还会 404/500。快照跟着消息走，历史回答可复现，也不需要额外网络请求。代价是快照占消息体积，且旧块不会跟随后续编辑。

02

404 只标不拦

2026-10-21 Lynx 拍：可看优先。抽屉继续渲染快照，只加一行「来源已删除」；不把引用变成不可点纯文本，也不返回 410。原 AC 的两条已被这次决定改写。

03

本轮 [n] 两步，跨轮一步

当前轮 [n] 先点亮右栏那一行，让用户看到「引用和命中是同一套编号」；跨轮引用不在右栏列表里，直接开抽屉，避免点了没反应。这是 2.3/2.4 交界处的交互取舍。

04

Resource 级删除判据

只查 GET /resources/:id，不逐 chunk 探测。实现简单、请求少，也符合「来源」的产品语义；代价是「只删了 chunk、资源还在」不会标已删除，这是当前边界。

  • 别把 500 当已删除：页面只认 ApiError 且 status === 404。后端挂了、代理返回 HTML、响应形状不对，都不会出现「来源已删除」；内容仍然可读，但标注保持沉默。
  • 别把 410 写回来：410 条款已在 2026-10-21 作废。当前后端没有 410 分支；如果以后加，前端也要把它归到「来源不在了」，而不是单独报错。
  • 粘贴内容的抽屉没有 dataUri：/ask 只在 source 非空时渲染链接；粘贴内容的 source 是 null，所以只显示 docTitle。唯一指针在 resourceId / dataUri 里，/recall 抽屉会显示，/ask 不显示——这是 AC「自动来源标识」的残差，不是代码笔误。
  • 抽屉的 a11y 不是 2.4 的功劳：portal、焦点归还、Esc、Tab 圈、滚动锁都在共享 Drawer 里；2.4 只负责内容和 open 状态。后来还有 2026-10-21 build5 的 a11y 补丁，不要把那些细节算进本 Story。
  • 字符级高亮没做：activeChunkId 只让右栏整行加底色和竖线；正文里不会把命中的那句话涂黄。2.4 的 AC 把字符级高亮列为增强项，当前不欠账。
  • GET 路由已经换人：2.4 当时是 routes/resources/resources.ts 手写 GET /:id，Epic 3 pre-3.2 换成 hono-crud read。今天如果改响应信封（不再是 { resource }），fetchResource 会抛形状错误，抽屉的「已删除」判断会静默失效。
