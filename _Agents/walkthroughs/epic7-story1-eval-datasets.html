03 · 小白词典

读代码前先认识六个词

都是日常后端概念，但在这格各有具体落点。

JSONB

能按对象查的 JSON 列

Postgres 的二进制 JSON。这里把“整套配置”塞进 config，加参数不用改表；代价是数据库不知道 k 该是正整数。

CHECK

行级布尔约束

CHECK (kind IN ('run','metric')) 这类断言由 DB 兜底；应用层会先校验一遍，给人类可读的 message。

RESTRICT / CASCADE

删父行时怎么对待子行

runs 用 RESTRICT：有 run 就删不掉数据集。cases 用 CASCADE：删数据集顺手删它的 case。

UPSERT

冲突就更新

INSERT … ON CONFLICT (dataset_id, case_key) DO UPDATE：导入题集可重复跑，同 key 覆盖而不是插入第二份。

content_prefix

块内容指纹

取块正文 trim 后前 80 字。7.2 跑评测前拿它对比现块：对不上说明资源被改过/重灌过，gold 失效。

迁移

dbmate 的 up/down

一个 SQL 文件两段：-- migrate:up 建表，-- migrate:down 逆序拆。主库与评测库跑同一套。

01数据集：名字唯一7.1

L3–13

name 唯一不是洁癖：导入脚本按名字找数据集，重名会让“灌进哪一个”变成猜。复制时由 repo 自动找空位（副本 / 副本 2）。

02runs 骨架：RESTRICT 就是删除保护7.1

L15–23

四列足够服务两件事：数 run 决定 409、让 baseline_run_id 有指向。OFF DELETE RESTRICT 是最后一道闸，路由会先数再删，给人类可读的「先删掉关联的 N 次运行」。

03case：唯一键与两条 gold 约束7.1

L25–42

(dataset_id, case_key) 唯一让导入幂等；jsonb_typeof(gold)='array' 挡「存成对象」；NOT negative OR gold='[]' 把“负例没有 gold”钉在库里。query / level / case_key 的非空也在这一层兜底。

04config：kind + jsonb，只保对象7.1

L44–56

运行配置和测评配置共用一张表，靠 kind 分家。DB 只保证 config 是 jsonb 对象——数值范围、模型在不在册，数据库管不了，也不该管。

05down 的顺序前置

L58–63

先拆 configs/cases，再拆 runs，最后 datasets；反过来会被外键拦住。这里没有 baseline 外键，所以不需要先 DROP CONSTRAINT。

13 · 取舍与踩坑

拍过板的地方，和踩过的坑

这些决定会一直影响 7.2/7.3，别在下一格推翻重来。

  • 一张配置表 + kind + jsonb（Lynx 拍板）：否掉了“运行配置一张表、测评配置一张表、每项一列”。换来的灵活性有代价：DB 不知道 k 该是正整数、min_similarity 该在 0..1 —— 所以校验必须住 API，且只能住一处（parseConfig）。
  • 循环外键不成立：baseline_run_id 指向 runs，runs 又指向 datasets。drizzle 生成的 schema 出现 TS7022/7024；运行期能跑、tsc 过不了。列保留、不加 FK，7.3 采纳基线时校验 run 属于该数据集。
  • drizzle-kit 的空串默认值 bug：text().default('') 被 introspect 成 default(')（未闭合字符串），生成文件直接语法错。修在 scripts/db-schema.mjs 的归一化 + 断言，而不是手改 schema.ts。
  • gold 必须块级且可复核：path 后缀可能命中多条资源（legacy 与 planning 的 ARCHITECTURE-SPINE 同名），导入选择“命中必须恰好 1 条”，失败不猜。15 条题集的块号逐条核对过含答案关键词（0.42、stepCountIs、租户…）。
  • content_prefix 是软指纹：80 字 trim 后比较，不是哈希。资源重灌后内容如果只是空白变化，前缀仍可能一致；7.2 的失效判断是“对不上就标 expected_chunk_missing”，不是安全校验。
  • 运行页仍是 mock：7.1 只把两个维护页接真；/evals 的运行历史、逐条结果、基线继续读 lib/evals-store（现在只存 runs）。别误以为“题集改了 run 会自动重跑”。
  • 审查修的三处：后缀匹配不再用 LIKE（_ / % 会被当通配符，实测能把 prd_7a87a934.md 错绑到 prd-7a87a934.md）；API 写入的 gold 统一 trim 且前缀截 80 字；配置数值加上界（k / topK / rrf ≤ 1000、temperature ≤ 2），避免 7.2 拿到离谱值。
  • 前端 live region 守卫：不要给条件渲染的提示条加 role="alert"——仓库的 repo-guard.test.ts 会拦；提示保持“可见条 + 常驻 sr-only role=status”的既有形状。
  • 切换数据库要重新导入：gold 的 data_uri 是目标库里解析出来的；共享模式写主库 uri，隔离模式带 eval/<hash>/ 前缀。换模式后题集必须在该模式再导一次，否则 gold 指不到本库的块。
