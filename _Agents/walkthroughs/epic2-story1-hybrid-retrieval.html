03 · GLOSSARY

小白词典：七个词够用

先有直觉，再看代码；每个词都对应本页真实出现的一个位置。

HNSW
一种近似最近邻索引，把向量组织成多层图，查询时走少数几条边就能靠近 topK。它换速度，接受“几乎总是对的”而不是“数学上一定全局最优”。
BM25
经典词法打分：词出现得越多、越稀有，分越高。ParadeDB 把它做进 Postgres，用 @@@ 操作符查询 chunks_bm25 索引。
RRF
Reciprocal Rank Fusion：不看原始分数，只看两路名次。每个名次的贡献是 1/(k+rank)，同一个 chunk 两路都命中就把两份贡献相加。
topK
每一路先取多少条候选。2.1 默认向量 10 条、词法 10 条；融合后再按 limit 截成送给上层的条数，默认 6。
余弦距离 / 相似度
pg 的 <=> 返回距离（0~2），相似度 = 1 − 距离。代码在 TS 侧换算，不把阈值写进 SQL 的 WHERE，否则会挡掉 HNSW 的 top-k 通道。
halfvec 与 partial index
halfvec(1024) 是半精度向量类型；partial index 是只索引满足条件行的索引。排序表达式必须与索引定义逐字同形，且保留 WHERE e.dimension = N，否则退化成全表扫描。
StageSink
3.3 的观测落点：每个 stage 的输入/输出/耗时交给 sink。没有 sink 时走 no-op；/retrieve 传 DB sink，chat 里的工具传 Langfuse sink。

07 · DECISIONS

取舍与踩坑：为什么长这样

从 2.1 的 code review 里挑了对理解影响最大的八条，外加七条会让人踩第二次的坑。

Review 拍板 / 补丁 / 记账：八条

  • D2 · 维度闸门不能 fail-open。 旧实现用空数组同时表达“库里没向量”和“体检没跑成”；后者会让向量路被 SQL 过滤成 0 条，而 BM25 照样命中，等于静默 BM25-only 作答——正是 AC 禁止的降级。拍板改成三态：数组 / 空数组 / null；null 抛 E_DIMENSION_UNKNOWN。DI 之后三态整体退役，改成每请求现查。
  • D5 · 全软删不另设话术。 评审时库里 5 行全软删，/chat 回“尚未添加任何资源”，与从没添加过无法区分。Lynx 选“改 AC”：为空 = 未软删行为 0，含全部已删除，不设第三种话术。
  • D6 · 命中响应体三处手抄。 /retrieve、/chat、前端 api.ts 各有一份逐字段映射；2.1 不单独抽 mapper，等 2.2 的 UIMessage 地基自然消解。今天仍是债务，换成工具 output 后字段形状又变了一次。
  • 补丁 · 五个旋钮进 config。 原本 topK/阈值/RRF k/defaultLimit 全硬编码，AC 的“可 env 覆盖”没实现。修法是五个 RETRIEVAL_* 进 config.ts，小数走新增的 floatOrThrow。
  • 补丁 · /chat 的 limit 与 try 范围。 评审发现 /chat 收了 limit 却没用，且 assemble 在 try 之外，文档承诺的 400/409 走不到。修法是 limit 打通到 retriever.search，assemble 移进 try，与 /retrieve 同口径。
  • 补丁 · count 的语义写进契约。 vectorCount / lexicalCount 是阈值过滤后的条数，不是召回条数；判“未找到”不能用 hits.length（已被 limit 截过）。这条如果不写，下一个人一定会读错。
  • D1 · 分层欠账先记账。 检索 stage 拿裸 pg.Pool 直查、recipes.ts 跨盒 import QwenEmbedder、ports/retriever.ts 被删，三处都违背 AD-1/AD-2。2.1 代码不动，登记进 deferred；2026-10-15 基础层迁移把直查库收进 Repo，2026-10-20 DI 把 embed 换成 EmbeddingHandle，契约仍住 retrieve/contracts.ts。
  • Defer · 检索没有 status='ready' 谓词。 两条 SQL 只过滤 r.deleted_at IS NULL，靠入库失败路径先删 chunks 兜住。这是跨层隐式不变量；修法是写进 SPINE，不是在本 story 偷加谓词。

踩坑清单：七个会重复踩的

  • 把问句裸交给 @@@。 那是查询语法解析器，不是分词器：语法字符直接抛错，全角冒号会静默漏检。正解是 paradedb.match_disjunction('content', q)。
  • 把阈值写进 SQL 的 WHERE。 1 - dist >= x 会挡掉 HNSW 的 top-k 通道；阈值必须在 TS 侧过滤，SQL 只负责按距离排序取 topK。
  • 把 halfvec 的 N 当绑定参数。 ::halfvec(N) 的 N 是类型修饰符，只能拼进 SQL 文本；拼之前必须 Number.isInteger 校验，这是该处唯一的注入防线。
  • 以为分数能判断“库里有没有答案”。 实测 WeKnora 怎么部署 在库里已无该主题时仍拿 0.5502，高于含糊问句的 0.5023；垃圾串在多喂两篇文档后从 0.4061 涨到 0.4589，顶穿 0.42。阈值只兜字符噪声。
  • 把 0 命中当错误。 2.1 的口径是 200 + 空 hits + 两个 count；空库/全无 ready 也是 200 答案体。非 2xx 会让 2.2 的 useChat 走错误通道。
  • 把 RRF 分当相似度。 双路 rank1 只有 0.03279，不是 0.9；代码也没做归一化。展示时按原始名次分，不要拿它和 cosine 比大小。
  • 软删壳让“空库”看起来正常。 resources 行还在、chunks 与 embeddings 已删；计数只看未软删行。并行会话里出现过 5 行软删壳，列表空但判定正常的情况，别误判成 bug。

被否掉的方案：① 维度体检失败就退回 BM25-only（D2 否掉）；② 用绝对相似度阈值决定拒答（实测顶穿，改交模型）；③ 为“全部删除”加第三种话术（D5 否掉）；④ 把 RRF 分归一化后再展示（2.1 不做）；⑤ 在 SQL 里做相似度过滤（会挡 HNSW）。
