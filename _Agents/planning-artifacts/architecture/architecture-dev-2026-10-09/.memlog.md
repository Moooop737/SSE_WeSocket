- (event) 工作模式=教练路;交付物默认=架构主线(收尾再确认是否加人看的说明文档)
- (decision) 范式=分层+端口适配器(半六边形)。两条独立路径:入库管线(fetch→parse→chunk→embed→存储端口)与问答运行时(编排层orchestration→检索端口→生成AI SDK→SSE)。检索/存储/Provider均为接口端口,ParadeDB/OpenAI为适配器。理由:P3工具化与P5 MCP扩展不改核心
- (decision) 持久化模型(参考../weknora WeKnora):chunks表与embeddings表分开。chunks=正文+定位(start_at/end_at,chunk_index)+index_status(ready/processing/failed);embeddings=向量(halfvec)+BM25文本content,按维度建HNSW。单人自用去掉tenant维度
- (decision) 检索=混合hybrid:向量相似度+ParadeDB pg_search/BM25(中文Lindera分词)。参考WeKnora默认vector+keyword双开
- (constraint) 维度是硬不变量:查询向量与入库向量须同模型同维度;HNSW按该维度建。定embedding模型即锁维度,解决PRD换Provider破坏向量一致性的隐患
- (decision) Embedding=Qwen3-Embedding + MRL自定义输出维降到1024维(避开pgvector halfvec HNSW硬顶4000;WeKnora现成索引也仅768/1024/3584)。embeddings.embedding存halfvec(1024),HNSW建在embedding::halfvec(dim)表达式上+行内dimension列+查询WHERE dimension=?同维cast(照WeKnora单表混维套路,单人自用也可简化为固定1024)
- (constraint) Provider实际为Qwen(百炼/DashScope OpenAI兼容协议)做embedding,非OpenAI;PRD的OpenAI假设需相应更正。查询向量必须1024维且与模型一致,否则报错(参考WeKnora错误码2201维度校验)
- (decision) 流式契约=沿用AI SDK UI Message Stream协议(前端useChat开箱解析)。引用照WeKnora做法:来源列表作为独立data part先于/随答案下发(WeKnora是references事件先行推送),正文用[1][2]标记+sources data part携带{marker,chunkId,docTitle,url,snippet}。MVP不做断线重连/continue-stream(WeKnora的StreamManager/Redis属过度,Deferred)。
- (decision) Provider定案:Embedding=Qwen3-Embedding经Ollama本地自部署(0.6B原生1024维,无需外部API);对话LLM=DeepSeek与百炼(DashScope)两家,均为OpenAI兼容协议,经AI SDK provider抽象可配置切换。API Key仅DeepSeek/百炼需要,存服务端env;Ollama本地无Key
- (correction) 更正PRD §9 OQ#2/addendum:原写OpenAI Provider不准确。实际embedding=本地Ollama(Qwen),chat=DeepSeek/百炼。AI SDK用openai-compatible provider接两家+ollama provider接嵌入
